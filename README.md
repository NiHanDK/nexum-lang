# NEXUM

**NEXUM** (Latin-inspired: connection, bond, relationship) is a token-efficient language for messages between AI agents. It is versioned, extensible without breaking changes, and every message translates to English deterministically.

```
@nx1.0 core cr>or done ^7
def $dc "ev-evita/app/Debt Collection"
ctx task:EVIT-1740
ac 4 part "Horten fallback lacks Customer No. filter"
f b "$dc/HortenAdvisMgt_IFPS.Codeunit.al#212" "applies by Document No. only" fix:"add SetRange(\"Customer No.\", ...)" ac:4
v part "AC 4 not met"
```

> Reply to #7 from code-reviewer (cr) to orchestrator (or): task finished.
> Acceptance criterion 4: partly met — Horten fallback lacks Customer No. filter.
> Finding (blocker) at ev-evita/app/Debt Collection/HortenAdvisMgt_IFPS.Codeunit.al#212: applies by Document No. only (suggested fix: add SetRange("Customer No.", ...); acceptance criterion: 4).
> Verdict: partly met — AC 4 not met.

## What is in this repository

| Path | What |
|---|---|
| `registry/` | **Source of truth.** The language as YAML: `language.yaml` (syntax, message types, value sets), `core.yaml`, `packs/*.yaml` |
| `budgets.yaml` | Locked size budgets for the agent cards |
| `dist/` | Generated by `npm run build`, never edited by hand: agent cards, `SPEC.md`, `translator.html`, `nx.mjs` (CLI), `registry.json` |
| `src/` | Runtime (parser, linter, translator), registry compiler, generators |
| `tools/` | Build, budget check, compatibility check |
| `examples/` | Valid example messages and an example roster |
| `templates/setup/` | Files for adding NEXUM to an agent setup |
| `.github/` | CI, release, steward and reviewer workflows; CODEOWNERS |

## Packs (1.0)

| Pack | Contents |
|---|---|
| `core` | 15 records every setup needs: references, context, acceptance criteria, findings, checklists, plan steps, outputs, errors, hypotheses, questions and answers, needs, verdicts, extension proposals, free text |
| `dev` | General software development: builds, tests, test cases, file changes, estimates, dependencies, HTTP calls |
| `bc` | Business Central and AL: objects, fields, events, permissions, upgrade code, report layouts, APIs |
| `bcops` | Business Central operations: telemetry (only for diagnostics/support agents) |

Read the full specification in [`dist/SPEC.md`](dist/SPEC.md). Agents learn the language from the cards in [`dist/cards/`](dist/cards/), see [`LEARN.md`](LEARN.md).

## Using it

Open `dist/translator.html` in a browser to translate messages, or use the CLI (Node 20+, no install needed):

```sh
node dist/nx.mjs translate examples/02-code-review.nx --roster examples/roster.yaml
node dist/nx.mjs lint examples/*.nx
node dist/nx.mjs card core dev
```

To add NEXUM to an agent setup, follow [`templates/setup/README.md`](templates/setup/README.md).

## Changing the language

See [`CONTRIBUTING.md`](CONTRIBUTING.md). In short:

- **Agents propose, the steward collects, the reviewer agent reviews, Nicolai approves.**
- Additions (new records, keys, values, packs) are MINOR versions. Breaking changes are MAJOR versions and only Nicolai can approve them.
- Budgets are locked: CI fails any change that exceeds them, with no override. Only a separate PR that changes `budgets.yaml`, approved by Nicolai, can raise them.
- Every released version stays available as a git tag and a GitHub release.

```sh
npm install
npm run check   # build + tests + budget check + compatibility check
```

## Repository setup (one-time, by the owner)

These settings live in GitHub and cannot be set from the code:

1. **Ruleset "Protect main"** (done): pull request required, Code Owner review required, stale approvals dismissed, status check `check` required, no deletions or force pushes. The repository is public because GitHub enforces rulesets on private repositories only on paid plans. Bypass: *Repository admin, for pull requests only*: PRs opened from Claude sessions are authored as the owner, and GitHub does not allow approving your own PR, so the owner merges those with the bypass. Direct pushes to `main` stay blocked, and CI must still pass.
2. **Secrets** (Settings → Secrets and variables → Actions):
   - `ANTHROPIC_API_KEY`: enables the steward and reviewer agents and exact token counting in the budget check. Without it, those workflows are skipped and the budget check uses a conservative estimate.
   - `NEXUM_BOT_TOKEN` (optional): a token from a bot (GitHub App or a separate account, not the owner's own token) with contents, issues and pull-requests write. With it, CI runs on the steward's pull requests. With only the default token, GitHub does not start workflows for PRs that a workflow created. Delete the secret rather than leave a placeholder in it.
3. **Setups that send proposals** need `gh` logged in with permission to open issues in this repository.
